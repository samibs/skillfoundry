# SkillFoundry v5.23.0 — Verification Layer

**Released:** 2026-07-07

---

## What's in This Release

2026's defining problem in AI-assisted coding isn't capability — it's **trust**. ~84% of developers use AI coding tools, but only ~29% trust the output, and 96% won't ship it unchecked. The burden shifted from *writing* code to *verifying* it.

That is SkillFoundry's founding thesis — enforced quality gates. v5.23.0 leans into it with three additions that **reuse the gates you already have**, applied more widely and earlier. The only new top-level command is `/verify`; the other two sharpen existing gates.

### `/verify` — the gates, turned outward

A new skill that runs SkillFoundry's existing gates against **any** code diff, not just `/forge` output:

```
/verify                 # working-tree diff
/verify --staged        # pre-commit gate
/verify --since main    # everything on this branch
/verify src/auth.ts     # specific files
/verify --quick         # BLOCKER-only fast pass (CI)
```

It composes `scripts/anvil.sh` (syntax, banned patterns, imports, Semgrep SAST), `/security` (adversarial review), `/layer-check` (three-layer reality), and the Anvil A3 self-adversarial lens — then emits a single **PASS / WARN / BLOCK** verdict. It's read-only (it judges, it doesn't fix), and it adds no new gate logic — only orchestration.

**Why it matters:** every other tool is a walled garden. `/verify` is the one thing a portable, agent-agnostic layer can do that a single-agent tool can't — hold code from Cursor, Copilot, Claude Code, Codex, Gemini, Grok, *or a human* to the same bar `/forge` enforces internally.

### PRD contradiction + gap detection

`/prd-lint` gains a semantic reasoning pass on top of its structural script. It reads the actual requirements and flags:

- **Contradictions** (→ FAIL): requirements the pipeline can't both satisfy — "stateless" vs. server-side sessions, a field a story uses that the data model never defines, a route described as both public and admin-only. Left in, the pipeline picks a side arbitrarily.
- **Gaps** (→ WARN; security/data → ERROR): undefined error behavior, missing authz rules, unaddressed edge cases, unmeasurable acceptance criteria, referenced-but-undefined entities.

This moves verification to the **cheapest possible point — before a line of code exists.** No downstream gate can catch a requirement that was wrong on purpose.

### Property-based testing

The `/tester` gate now treats property-based tests as a first-class category: assert invariants across **generated** inputs (fast-check / Hypothesis / jqwik) rather than only hand-picked examples — round-trip (`decode(encode(x)) == x`), idempotence, bounds/invariants, never-throws-on-valid-input, oracle comparison. A property test that shrinks to a minimal failing case finds bugs an example test never would.

## Competitive context

The market converged on SkillFoundry's verification thesis, and AWS Kiro began contesting the PRD-first space with two techniques SkillFoundry lacked — automated spec-contradiction checking and property-based tests. v5.23.0 closes both, and turns the gates outward with `/verify`.

## Upgrade Notes

- **No breaking changes.** `/verify` is additive; `/prd-lint` and `/tester` are enhanced (structural lint and existing test behavior unchanged).
- Skill count is now **108 per platform** (`/verify` added), generated across all six install platforms.
- Safe update via `git pull` / `./update.sh`.
