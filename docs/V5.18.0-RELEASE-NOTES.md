# SkillFoundry v5.18.0 — Web Security Checker

**Released:** 2026-06-12

---

## What's in This Release

v5.17.0 introduces `/web-security-check` — a mandatory gate that validates the **live deployed surface** of web applications before production promotion. It fills the gap that static code analysis can't: headers that only exist at runtime, certificates that expire silently, cookies that ship without flags, DNS that was configured once and never checked again.

This is not a code review tool. It talks to the actual running server.

---

## The Problem

The existing deployment gate sequence (secure-coder → security-guardian → test-coverage-guardian → dependency-auditor → compliance-verifier → production-orchestrator) validates **code**. None of those gates check:

- Whether the server is actually serving HTTPS
- Whether the TLS certificate is valid and not expiring in 3 days
- Whether session cookies have `Secure` and `HttpOnly` flags on the live response
- Whether HSTS is present on the deployed URL (not just in the config file)
- Whether `.env` or `.git/config` accidentally ended up in the web root

These misconfigurations are invisible until an attacker finds them — or until an auditor asks for evidence.

---

## The Solution: `/web-security-check`

A live URL validation gate with 10 check groups, tiered severity, and evidence-first execution.

### 10 Check Groups

| # | Group | BLOCKER Example | WARN Example |
|---|-------|----------------|-------------|
| 1 | TLS/Certificates | Expired cert, invalid chain | Expiry <30 days, TLS 1.2 only |
| 2 | HTTP Security Headers | HSTS absent on production | CSP missing, X-Powered-By exposed |
| 3 | Cookie Security | Session cookie missing `Secure` or `HttpOnly` | `SameSite` not set |
| 4 | DNS/Mail Security | — | SPF/DKIM/DMARC missing or `p=none` |
| 5 | Information Leakage | `/.env` returns 200, stack trace on 500 | Server version in headers |
| 6 | Redirect Chain | HTTP served in plaintext, redirect loop | >3-hop chain |
| 7 | Open Ports | DB port (3306/5432) exposed | Admin port (8080) exposed |
| 8 | WHOIS/Domain Expiry | Domain expired | Expiry <30 days |
| 9 | Dependency Fingerprint | — | Outdated JS lib with CVE >7.0 |
| 10 | WAF/Rate Limiting | — (INFO only) | — (INFO only) |

### Severity Model

| Level | Gate Behaviour |
|-------|---------------|
| **BLOCKER** | Stop promotion. No exceptions. Fix required before re-run. |
| **WARN** | Hold promotion pending lead sign-off. Must be acknowledged. |
| **INFO** | Logged. No gate action. |

### Evidence-First Execution

The agent does not self-certify. It runs real commands against the live URL:

```bash
openssl s_client -connect domain:443 </dev/null  # TLS check
curl -sI -L https://url                          # headers + cookies
curl -sI http://domain                           # redirect check
dig domain TXT && dig _dmarc.domain TXT          # DNS/mail
curl -o /dev/null -w "%{http_code}" https://domain/.env  # leakage probe
whois domain | grep -i expir                     # domain expiry
```

### Mandatory Closing Block

Every invocation ends with:

```
WEB SECURITY SCORE: [0-100]
BLOCKERS: [n] ([list])
WARNINGS: [n] ([list])
TLS: [PASS|FAIL|WARN] — cert expiry [date]
HEADERS: [n/8 compliant]
DNS/MAIL: SPF=[...] DKIM=[...] DMARC=[...]
COOKIES: [PASS|FAIL|N/A]
INFO LEAKAGE: [CLEAN|EXPOSED — detail]
OVERALL: [APPROVED FOR PROMOTION | BLOCKED — n blocker(s) must be resolved]
```

Score: 100 − (15 × BLOCKERs) − (5 × WARNs).

## Operating Modes

| Command | Scope |
|---------|-------|
| `/web-security-check <url>` | Full check — all 10 groups |
| `/web-security-check <url> --headers` | HTTP security headers only |
| `/web-security-check <url> --tls` | TLS/cert only |
| `/web-security-check <url> --dns` | DNS + mail security only |
| `/web-security-check <url> --quick` | BLOCKER-only fast gate (for CI/CD pipelines) |
| `/web-security-check <url> --report` | Full check + JSON artifact to `logs/web-security/` |

---

## Pipeline Integration

`web-security-checker` is now a mandatory gate in the deployment sequence:

```
secure-coder
  → security-guardian
  → test-coverage-guardian (≥95%)
  → dependency-auditor
  → compliance-verifier
  → web-security-checker    ← NEW (public-facing projects)
  → production-orchestrator
```

**Position:** After staging deploy, before production promotion. Requires a live URL.

**Exceptions (skip with justification):**
- Internal tools with no public URL
- Non-web projects (CLI tools, libraries, background workers)
- Local development environments

## What This Does NOT Do

- Does NOT replace `/security` (static code analysis, OWASP code review)
- Does NOT replace `/pentest` (adversarial exploitation)
- Does NOT run before deployment — it requires a live URL
- Does NOT apply to internal tools or non-web projects
- Does NOT perform load testing or DDoS probing
