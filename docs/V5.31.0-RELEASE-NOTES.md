# SkillFoundry v5.31.0 — Governed Development Mission Protocol

**Released:** 2026-09-04

---

## What's in This Release

Two changes ship together, both additive and opt-in:

1. **The Governed Development Mission Protocol** — a durable, repository-resident record of
   engineering truth that survives the agent that produced it.
2. **AgentOS `enforce` mode** — the final stage of the output-contract rollout begun in v5.29.0.

Nothing changes for an existing project until it starts a mission or flips the contract mode.

---

## The problem: run state dies with the run

SkillFoundry already tracked a lot — worktrees, a run-state machine, an audit trail, gate
evidence, scope validation, parallel dispatch. But all of it lives in `.skillfoundry/runs/`,
describes a single execution, and disappears when that execution ends.

So the next agent — a new session, a different model, a colleague's machine — starts from
nothing but chat history. And chat history is the least reliable record in the system.

This release adds the durable half: a `.ai/` control plane committed to the repository.

```text
Git             what exact content changed over time
Attestation     where, and under what conditions, did the worker operate
Patch guide     what changed and why
Evidence        what proves the implementation satisfies the requirement
Ledger          what is the project's current authoritative engineering state
──────────────────────────────────────────────────────────────────────────
                = governed engineering history
```

A replacement worker with zero context reconstructs project state from that, not from a
transcript.

## Enforcement is code, not prose

The distinction that matters: agents do **not** hand-write `.ai/*.json`. Seven TypeScript
modules write and validate it, and refuse claims the repository cannot substantiate.

```
/mission set STORY-042 acceptance_status PASS

  ✗ Refused: acceptance_status stays NOT_STARTED

  The ledger must never claim more than evidence proves:
    · acceptance_status=PASS blocked by unsatisfied AC dispositions: AC8=BLOCKED_BY_AUTHORIZATION
    · acceptance_status=PASS blocked by open gaps: GAP-001
```

A promotion to a terminal status is gated on the artifact that would prove it:

| Status | Requires |
|---|---|
| `implementation_status = COMPLETE` | a worker SHA **and** an existing patch guide |
| `acceptance_status = PASS` | evidence present on disk, every AC dispositioned, no blocking gaps |
| `integration_status = INTEGRATION_VALIDATED` | provenance that is not `LOST` / `UNKNOWN` |
| `publication_status = PUBLISHED` | a remote-verified SHA **and** tree |

## The lifecycle is never one vague status

Five dimensions advance **independently**, because a feature can be implemented but not
accepted, accepted but not externally validated, accepted but not published:

```text
implementation_status        COMPLETE
acceptance_status            EVIDENCE_PARTIAL
integration_status           NOT_STARTED
publication_status           NOT_STARTED
external_validation_status   NOT_APPLICABLE
```

Alongside these sits an `execution` block — wave, agent, branch, worktree, base SHA,
dependencies, write manifest — so one ledger entry answers both *"is this scheduled and
running?"* and *"is this claim proven?"*. `/mission reconcile` cross-checks the two: a
scheduler that reports `INTEGRATED` while the evidence gate disagrees is a reported
discrepancy, not an accepted fact.

## What it catches that a green test run does not

**"Tests passed" while the runner hung.** Normal termination and orphan detection are
acceptance criteria. A run that timed out, was signalled, or left processes alive in its
process group is reported `NOT A CLEAN VALIDATION` — never scored as PASS.

**A dev server orphaned after the run.** Every started process is recorded with an identity
fingerprint of its live command line. Cleanup re-verifies the PID before signalling, so a
recycled PID belonging to another project is refused rather than killed. Blanket
`pkill node`-style cleanup is impossible by construction.

**A change silently dropped during a merge.** Provenance uses `git patch-id --stable`, so a
cherry-pick onto a moved baseline is provably the same contribution. The final tree is then
verified blob-by-blob: `PRESERVED`, `SUPERSEDED_BY_AUTHORIZED_CHANGE`, `LOST` or `UNKNOWN` —
and the last two block acceptance.

**"Pushed" mistaken for "published".** A successful `git push` is not proof.
`/mission publish-check` re-fetches and confirms the remote SHA, tree and contribution
content, or reports `PUBLICATION_FAILED`.

**"It was probably already broken."** That claim now requires a baseline run — the same test,
the same environment, at the accepted baseline SHA. Without it the claim is *not
substantiated* and the failure is attributed to the current mission.

**Retry loops that burn budget.** Two consecutive attempts producing an identical failure
signature with no state change is `NO_PROGRESS`: stop and report the blocker.

**Fixing working code to compensate for a broken environment.** Failures are classified by
origin — `ENVIRONMENT_DEFECT`, `WORKTREE_DEFECT`, `REPOSITORY_SNAPSHOT_INCOMPLETE`,
`INFRASTRUCTURE_DEFECT`, `EXTERNAL_DEPENDENCY`, `AUTHORIZATION_FAILURE` — before any
remediation. An assertion failure is only MEDIUM confidence for `PRODUCT_DEFECT`.

## Multi-agent execution

`MULTI_AGENT_PROTOCOL.md` ships into every scaffolded project. Its central rule:

> Parallelize independent work, serialize dependent or colliding work, and make all execution
> state recoverable without relying on chat memory.

- **One global dependency graph** across all PRDs, with `HARD` / `SOFT` / `INTEGRATION` edges
  and cycle detection. A cycle schedules nothing; it is reported for a human to break.
- **Collision-aware wave planning.** `/mission wave plan` admits items one at a time and
  *defers* any that would collide, escalating shared architectural primitives — routing, DI
  bootstrap, migrations, lockfiles, auth — to `HARD_COLLISION`.
- **One git-native worktree per writer.** Registering a second write agent for an occupied
  worktree is refused. A copied repository folder is never accepted as a worktree; only
  `git worktree list --porcelain` proves it.
- **No source writes before attestation.** `/mission attest` machine-collects proof of worktree
  registration, a clean product tree, commit capability and required assets;
  `/mission gate` fails closed.
- **Serial integration in dependency order**, never worker completion time.

Parallel implementation is not parallel merging.

## Try it

```bash
/mission init STORY-042 --title "JWT refresh rotation"
/mission attest STORY-042 --worker claude-coder-042 --agent claude
/mission gate STORY-042                      # WRITES AUTHORIZED / BLOCKED

  ... implement ...

/mission evidence STORY-042 --kind tests --run "npm test"
/mission commit STORY-042
/mission verify STORY-042                    # Definition of Done
```

Run `/mission help` for all 25 subcommands, or read `MULTI_AGENT_PROTOCOL.md`.

## Part 2 — AgentOS `enforce` mode

The final observe → warn → **enforce** stage of the output-contract rollout. A fourth tier for
`message_contracts` (`off | permissive | strict | enforce`) and `SF_BUS_CONTRACTS`.

In `enforce`, agent output contracts become **binding**: an agent whose structured result
violates its contract is downgraded to `failed`, rather than merely logged. Agent system
prompts gain an additive instruction to append a fenced ```json block matching the contract —
the agent still produces its normal prose and code, so existing text consumers are unaffected.

Off by default. Prose-only results are never a violation, so free-text agents are never failed.

## Compatibility

- **Fully backward-compatible and additive.** No existing command, gate, or pipeline changes
  behavior. Projects without a `.ai/` ledger are unaffected. A ledger written before the
  execution plane existed is normalized on read.
- Evidence payloads are redacted and size-bounded at 256 KiB before they are written — no
  secret value and no megabyte log reaches `.ai/`. Raw logs live outside git in
  `.skillfoundry/mission-logs/` and are referenced, never inlined.
- All git invocations use `execFileSync` with argument arrays. Mission IDs, agent names, worker
  names and evidence paths are validated so none can escape the artifact tree.
- Ledger, gaps, catalog, attestation, agent, process and evidence writes are atomic
  (temp + rename), so a crash mid-write leaves the last valid document intact.
- `--force` exists for human override and records the bypassed claims, which then surface in
  `/mission reconcile` as discrepancies rather than disappearing.

## Tests

**296 new tests across 8 files, all passing.** Integration-style rather than mocked: the suite
creates real git repositories, real linked worktrees, real bare remotes and real cherry-picks,
and spawns real child processes to exercise orphan detection, ownership verification and
PID-recycling refusal.

Three real defects were found by dogfooding the protocol on SkillFoundry itself and fixed
before release:

1. `/mission init` dirtied the working tree, so the next `/mission attest` failed on the
   artifacts it had just created. Cleanliness now separates *product* from *governance* changes.
2. A mistyped command exited 0 and was recorded as `CLEAN VALIDATION` with zero tests run —
   exactly the false green the protocol exists to prevent. A `--kind tests` run with no
   detectable results is now not-clean.
3. The vitest output parser reported 8 (test *files*) instead of 295, matching the `Test Files`
   line first. Evidence that misstates what was validated is worse than evidence reporting
   nothing.

Pre-existing failures on `main` (`agent-prompt-loader`, `gates`, `health-check`,
`dependency-scanner`) were confirmed unrelated by running the same files with the release
changes stashed and restored — an identical failure set both ways.

## Final principle

> A worker saying "done" is not evidence. A commit is not acceptance. A passing test without
> normal termination is not a clean validation. An integration is not a publication. A
> publication without remote verification is not proven.
