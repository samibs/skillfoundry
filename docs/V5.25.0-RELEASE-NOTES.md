# SkillFoundry v5.25.0 — Security & Robustness Hardening

**Released:** 2026-07-07

---

## What's in This Release

SkillFoundry was put through a full **adversarial audit of its own codebase** — the same brutal treatment the framework applies to the code it reviews — followed by remediation. Every CRITICAL/HIGH finding was verified against source before being fixed, and every fix ships with a regression test. The full suite runs at **2352 passing** (the only 3 failures are pre-existing environmental flakes: provider-ping timeouts and one shell-out timeout).

This is a hardening release: no new commands (skill count stays 108/platform). The only new surface is behavioral — two env flags (`SF_SPECTER_SIMULATE`, `SF_PRD_GATE`) and one pool API (`submitBatchSettled`).

### Closed real RCE / exfil paths (P0)

- **Specter no longer executes model-authored shell commands.** The default pipeline's SPECTER phase ran `execSync(vector.exploitSimCommand)` on raw LLM output behind a guard that returned true for any command without "curl"/"http". A poisoned PRD or diff could drive it to run an arbitrary command unattended. It now never runs the model's command: it extracts and validates a loopback URL (WHATWG parser, exact loopback host, no userinfo — defeating the `localhost@attacker.com` trick) and issues a fixed `execFileSync('curl', …)`. Simulation is opt-in via `SF_SPECTER_SIMULATE` (default **off**); static vector generation + mitigation advice still ship.
- **Permission `ask` fails closed in headless runs.** In autonomous `forge`/`go` runs with no interactive approval channel, an `ask` verdict fell through to execution — silently auto-approving writes, shell, `git push`. It now denies when no approval channel exists.
- **`grep` tool and semgrep scanner de-shelled.** Both built shell strings from model/repo input (`JSON.stringify` is *not* a shell escaper — bash evaluates `$()` inside double quotes), so a crafted pattern was RCE even with `allow_shell=false`. Both now use `execFileSync` with argv arrays.
- **Path-boundary sibling escape fixed** — `startsWith(dir)` without a separator let `/proj` match `/proj-secrets`.

### Real memory isolation & sanitization (P0)

- **Per-project memory isolation.** Recall had zero namespacing (0 of 650 live entries were stamped) and commingled 5+ unrelated private projects, so `/recall` in one project surfaced another's decisions as authoritative context. `capture()` now stamps a project key and recall (both `memory.ts` and the layered-recall path behind `/memory-search`) filters by the active project; legacy/unstamped and explicit universal entries stay shared.
- **Sanitizer hardened.** The pre-push knowledge sanitizer under-matched on both axes — its secret regex anchored on `KEY=` while the data is JSON (`"api_key": …`), and its path rule only matched a literal `projects/` segment — so usernames and private project names were one `knowledge-sync init` away from a public repo. It now catches JSON-embedded secrets, token formats (`sk-`, `ghp_`, `AKIA…`, JWT, PEM) and emails, strips usernames/project names generically, and **masks values in place** instead of dropping (and corrupting) whole entries. Verified on the live corpus: 530 paths normalized, 0 usernames remaining, 0 JSON corruption.

### Gates that actually gate (P1)

- **Fail-closed across the board.** The PRD quality gate (was `continue` on scoring error → `SF_PRD_GATE=soft` opts out), the **T4 security gate** and **anvil SAST** (silent PASS when gitleaks/semgrep absent → now WARN/BLOCK on degraded coverage), and the **security micro-gate** (unparseable verdict → FAIL) now all fail closed instead of waving code through.
- **Certification no longer rewards absence of code.** Categories with nothing to scan returned a perfect 100, so a near-empty repo graded ~B. N/A categories are now excluded from the average, and a substance floor caps a codeless project at grade F.
- **Honest gate parallelism.** `runAllGates(parallel)` never actually ran concurrently (synchronous `execSync`) — the false claim was removed.

### Runtime robustness (P1)

- **AgentPool no longer deadlocks on a hung task.** The per-task timeout only *requested* abort; an agent that ignored it never settled, so its slot never freed and the whole pool stalled. The timeout now force-settles the task. Also: `submitBatchSettled` for resilient batches, shutdown cleanup moved to `finally` (no leaked interval/subscription), and `drainTimeout ≥ taskTimeout`.
- **Message bus recipient isolation.** Direct-addressed messages no longer reach every type-matching subscriber — subscribers can declare an identity the bus enforces.

### Fragmentation cleanup

- Malformed tool-call args are now repaired + logged instead of silently becoming `{}` (wiring the previously-dead `output-repair.ts` into the provider path); three divergent `runCommand` clones consolidated into one shared util; the colliding `GateResult` type renamed; the anvil A-tier count contradiction and `t`-prefix collision fixed.

### Deliberately deferred (with rationale)

Consistent with the framework's surgical-change / no-fake-fix discipline, four audit items were flagged rather than force-fixed: the broad **gate-verdict casing unification** (a latent hazard where the code is currently correct; a ~50-site sweep risks introducing the bug it prevents), the **6-way intent-router doc/runtime gap** and **37 registry agents on stub prompts** (product decisions, not mechanical fixes), and the **full swallowed-catch sweep** (the security-relevant ones were fixed).

## Upgrading

Safe feature update — no migration, no breaking changes. New behavior is opt-in via `SF_SPECTER_SIMULATE` and `SF_PRD_GATE`.

./update.sh
