# SkillFoundry v5.27.0 — Skill Rationalization & `/prune`

**Released:** 2026-07-13

---

## What's in This Release

A new capability and a disciplined cleanup.

**`/prune`** removes dead code and duplicate code with a real detection engine. And a
**skill-rationalization pass** trimmed the framework from **109 → 97 skills with zero
capability lost** — SkillFoundry had accumulated *prompt-era scaffolding* (redundant personas,
thin "guardian" role cards) built to force weaker models into rigor. Smarter models need fewer,
sharper tools. The scaffolding is gone; the good content was kept or promoted to universal
modules.

The guiding rule throughout: **remove scaffolding, never quality.** Several skills that looked
like deletion targets turned out to be genuinely valuable (red-team-researcher, security-scanner,
the senior-engineer discipline) and were kept or universalized instead.

## New: `/prune` — Dead Code & Duplication Remover

A dedicated skill for finding and safely removing dead code and duplication, backed by a real
detection engine (`scripts/prune-scan.sh`) — not prompt guesswork.

- **Duplicate blocks** via N-line window matching (cross-file).
- **Unused imports** (JS/TS/Python) with a safe `--fix` that removes only import statements
  whose every binding is unused (whole-line, deleted in descending order so shifts can't
  corrupt each other).
- **Unused-export candidates** (JS/TS), reported only.
- `--deep` also runs `jscpd` / `knip` / `depcheck` when installed. Excludes `node_modules`,
  `dist`, `build`, `.next`, `vendor`, `__pycache__`, `*.min.js`, `*.d.ts`.

**Safe by default:** only fully-unused imports are auto-removed. Unused exports and duplicate
blocks are reported for review — an export may be an entry point, and de-duplication is a
refactor (extract shared code), not a deletion.

```
/prune                    # scan: unused imports/exports + copy-paste blocks
/prune deadcode --fix     # remove fully-unused imports (safe subset only)
/prune duplicates         # locate copy-paste blocks to extract
```

## Skill Rationalization (109 → 97)

Six focused passes, each its own PR with the full test suite green between:

- **Removed cruft** — three `upgrade-*` "skills" that were migration notes ("Upgrade
  documentation… evolution from X to Y"), and `agent-index` (a static architecture reference).
- **Security consolidation** — folded `/pentest` into `/security` (which already had a pentest
  mode + OWASP + STRIDE); retired the `security-guardian` role card and moved its veto/escalation
  authority to `/security`. **Kept** `red-team-researcher` (the best-written security skill) and
  `security-scanner` (514 lines of real scan logic).
- **Guardian role cards** — retired `performance-guardian`, `test-coverage-guardian`,
  `regression-prevention`, and `build-stability` (identical ~65-line VETO/escalation boilerplate),
  reassigning their governance roles to `tester` / `verify` / `sre`. Their concrete threshold
  rules (≥95% coverage, load-test ≥1000 users, blast-radius, red-pipeline-blocks) were preserved
  in `_bpsbs-production-rules.md`, not lost.
- **Coder cluster** — merged `secure-coder` and `senior-software-engineer` into `/coder`.
  secure-coder's Documentation Contract was grafted in; senior-engineer's excellent discipline
  (assumption-surfacing, anti-sycophancy push-back, declarative-over-imperative) was
  **universalized** into `_coding-discipline.md`, so *every* agent gets it — not one opt-in skill.

The `_governance-model.md` role hierarchy was simplified along the way (collapsed duplicate
tiers, fixed a nonsensical self-escalation).
