# SkillFoundry v5.19.0 — Structural Trust & Production Resilience

**Released:** 2026-06-22

---

## What's in This Release

v5.19.0 addresses the structural gaps that surface when SkillFoundry moves from solo developers to teams, from planned features to production incidents, and from fresh projects to established codebases with their own conventions.

Four themes drive this release:

1. **Isolation** — Concurrent developers can no longer corrupt each other's pipeline state.
2. **Adaptation** — The framework learns your conventions instead of overriding them.
3. **Resilience** — Production incidents have a dedicated pathway that bypasses gates safely, with mandatory debt tracking.
4. **Trust** — The evaluator improves over time. Every gate decision is recorded permanently.

---

## The Problems

### Multi-user state corruption

`.claude/` state files (`testloop-state.json`, `feature-state.json`, `execution-context.json`) were flat in the `.claude/` directory. Two developers on the same repo — or the same developer on two machines — would silently overwrite each other's session state. A feature-in-progress on machine A would read corrupted state from machine B's last pipeline run. Git would commit session artifacts that belong on no machine but the one that wrote them.

### Convention override

SkillFoundry assumes conventional commits, `CHANGELOG.md` in keepachangelog format, and `*.test.ts` colocated test files. A project using `CHANGES.rst`, JIRA-format commits, and `test_*.py` in a `tests/` directory gets the wrong changelog entries, wrong commit format, and wrong test file names — silently.

### No hotfix path

The full pipeline (shadow tester, Anvil, evaluator, TestLoop up to 5 iterations, docs generation) is appropriate for planned features. It is harmful during a production incident. There was no legitimate bypass — developers either forced commits around the pipeline or used `--override` in ways it wasn't designed for.

### Evaluator trust collapse

The evaluator is an LLM. It will occasionally flag intentional project decisions as violations — rate limiting at the API gateway, public health endpoints, HS256 in test helpers. With no feedback mechanism, each wrong verdict costs developer trust. The only response was to `--override` it, which doesn't fix the underlying judgment.

### No durable audit trail

Override decisions in `logs/overrides.md` and evaluator verdicts in commit bodies are destroyed by force-push, branch deletion, or repo migration. There was no external record of what was approved, bypassed, or hotfixed.

## The Solutions

### State Isolation

`.claude/` is now split:

```
.claude/local/     gitignored — machine-specific session state
  execution-context.json
  testloop-state.json
  testloop-results.json
  feature-state.json
  semgrep-results.json

.claude/shared/    committed — team-visible configuration
  config.json
  stack-profile.json
  conventions.json
  evaluator-calibration.json
  team-profile.json
```

`.gitignore` updated to exclude `.claude/local/`. Path references migrated in `testloop.md`, `feature-lifecycle.md`, `_execution-context.md`, `_stack-profile.md`, `onboard.md`, `quick.md`.

### Convention Discovery

New protocol module `agents/_convention-discovery.md` runs during `/onboard` and outputs `.claude/shared/conventions.json`:

```json
{
  "changelog": { "format": "keepachangelog", "file": "CHANGELOG.md" },
  "commits": { "format": "conventional", "scope_used": true, "ticket_pattern": "STORY-\\d+" },
  "tests": { "naming_pattern": "*.test.ts", "location": "colocated" },
  "docs": { "api_file": "docs/api_reference.md", "docstring_style": "jsdoc" }
}
```

All agents that write commits, changelogs, or test files read this file. Override via the `overrides` section in `conventions.json`.

### Hotfix Pathway

`/hotfix "incident description"` runs:

1. Semgrep hard-block scan (always active — no credentials can ship even in hotfix mode)
2. Implement the minimal fix
3. Smoke test (max 2 iterations, changed files only)
4. Commit with hotfix prefix + bypass disclosure
5. Create `genesis/hotfix-followup-*.md` (mandatory — describes what was bypassed and what must be done)
6. Append `hotfix_applied` entry to `logs/audit-trail.jsonl`

Bypassed gates: shadow tester, Anvil, evaluator, full TestLoop, docs generation.
Never bypassed: Semgrep hard blocks, audit trail.

### Evaluator Calibration

```bash
/evaluator --feedback "finding 2 was wrong — rate limiting is at the API gateway (Kong), not in services"
```

Appends to `.claude/shared/evaluator-calibration.json`. Every future evaluation prepends this context:

```
PROJECT CALIBRATION CONTEXT
[cal-001] Rate limiting: handled at API gateway (Kong), not in services.
[cal-002] /health /status /metrics: intentionally public, no auth required.

These calibrations were recorded by the development team.
```

Calibrations are context (not rules) — the evaluator can still override them with specific new evidence. Use `--confirm-calibration <id>` to mark a calibration as team-verified. Use `--list-calibrations` to review accumulation.

### Audit Trail

`agents/_audit-export.md` defines an append-only `logs/audit-trail.jsonl`:

```bash
# All overrides in the last session
grep '"type":"override_decision"' logs/audit-trail.jsonl | tail -20

# All hotfixes
grep '"type":"hotfix_applied"' logs/audit-trail.jsonl

# Overrides by user
grep '"type":"override_decision"' logs/audit-trail.jsonl | grep -o '"user":"[^"]*"' | sort | uniq -c
```

Optional webhook: set `audit_webhook` in `.claude/shared/config.json` to POST entries to an external system (5s timeout, non-blocking, silent on failure).

### Global Profile Resolution

`~/.claude/skillfoundry-profile.json` is a personal profile applied to every new project. Teams can publish a team profile at `.claude/shared/team-profile.json` (pulled with `/onboard --team-profile <url>`). Resolution: global → team → project config → CLI flags.

---

## Breaking Changes

None. All changes are additive or path migrations. Existing pipelines continue to work.

The path migration (`.claude/X` → `.claude/local/X` or `.claude/shared/X`) is transparent to agents — they read from the new paths, falling back gracefully if files don't exist.

---

## Scope

Operates entirely within the `.claude/` directory and `agents/` protocol files. No changes to `sf_cli/`, `mcp-server/`, or any runtime code.
