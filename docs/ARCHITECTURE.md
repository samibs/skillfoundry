# SkillFoundry Architecture

Internal structure and runtime behavior of the framework. This document is for contributors
and for anyone extending SkillFoundry. For installation and day-to-day usage, see the
[README](../README.md).

---

## The Two Systems

SkillFoundry ships two independent execution systems that share the same agent contracts,
quality gates, and memory bank.

| | Standalone CLI (`sf`) | IDE Skills |
|---|---|---|
| Implementation | Node.js + React/Ink terminal app (`sf_cli/`) | Markdown instruction files (`agents/` → platform dirs) |
| Execution | Own provider connection, own agentic tool loop | Executed by the host AI tool |
| Pipeline | Self-contained `sf forge` implementation | Skill orchestrating sub-agents |
| Provider | Selected in `.skillfoundry/config.toml` | The host tool's provider |
| Budget controls | Enforced in-process before each call | Not available (host controls spend) |

`/forge` exists in both systems and they are **different implementations**. The IDE skill
orchestrates sub-agents through the host tool; the CLI command runs the pipeline itself.

## Pipeline

```
                    ┌─────────────┐
                    │   /prd      │  Write requirements
                    └──────┬──────┘
                           │
                    ┌──────▼──────┐
                    │   /go       │  Validate → generate stories → implement
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
        ┌─────▼─────┐ ┌───▼───┐ ┌─────▼─────┐
        │ Architect │ │ Coder │ │  Tester   │  Agent pipeline
        └─────┬─────┘ └───┬───┘ └─────┬─────┘
              │            │            │
              └────────────┼────────────┘
                           │
                    ┌──────▼──────┐
                    │ Micro-Gates │  MG0 AC · MG1 security · MG1.5 test docs
                    │             │  MG2 standards · MG3 cross-story
                    └──────┬──────┘
                           │
                    ┌──────▼──────┐
                    │  The Anvil  │  T0-T6 quality gates
                    └──────┬──────┘
                           │
                    ┌──────▼──────┐
                    │  /security  │  OWASP scan + credential check
                    └──────┬──────┘
                           │
                    ┌──────▼──────┐
                    │   /gohm     │  Harvest lessons → memory_bank/
                    └──────┬──────┘
                           │
                    ┌──────▼──────┐
                    │ knowledge   │  Sync to global repo (optional)
                    │    sync     │  Lessons available in all projects
                    └─────────────┘
```

`/forge` runs this pipeline in one command: it discovers PRDs, generates stories, implements
each story with the agentic tool-use loop, runs micro-gates per story (MG1 security + MG2
standards, MG3 cross-story review), runs the Anvil tiers with auto-fixer retries, persists run
metadata, and harvests knowledge entries (run summaries, errors, gate verdicts) to
`memory_bank/knowledge/*.jsonl`.

### Quality gate tiers

| Tier | Check |
|------|-------|
| T0 | Correctness contract |
| T1 | Banned patterns and syntax |
| T2 | Type check |
| T3 | Tests |
| T4 | Security scan |
| T5 | Build |
| T6 | Scope validation |

Micro-gates are lightweight reviews at handoff points. MG0 validates that acceptance criteria
are objectively testable (static, no AI call). MG1 (security) and MG2 (standards) run after
each story and trigger the fixer automatically on failure. MG1.5 checks test documentation
quality and re-triggers the tester. MG3 reviews cross-story consistency before the TEMPER
phase and is advisory only.

Delivery budgets decide how much of this pipeline a given change warrants — see
[DELIVERY-EFFICIENCY.md](DELIVERY-EFFICIENCY.md).

## Tool System

The agentic loop executes tools under permission control, with dangerous-command blocking.

| Tool | Icon | Purpose |
|------|------|---------|
| `bash` | `▸` | Run shell commands |
| `read` | `◉` | Read files with line numbers |
| `write` | `◈` | Create or overwrite files |
| `glob` | `✶` | Find files by pattern |
| `grep` | `≣` | Search file contents |
| `debug_start` | | Start a debug session (Node.js) |
| `debug_breakpoint` | | Set / remove / list breakpoints |
| `debug_inspect` | | Inspect scope, callstack, variables |
| `debug_evaluate` | | Evaluate expressions in the paused frame |
| `debug_step` | | Step over / into / out / continue / pause |
| `debug_stop` | | Terminate the debug session |

Permission modes: `auto` (reads auto-approved, writes ask), `ask` (prompt every time),
`trusted` (allow all), `deny` (block all).

### Debugger internals

- Spawns `node --inspect-brk=0` with source-map support.
- Connects over the Chrome DevTools Protocol via a custom MinimalWebSocket (Node 20
  compatible, no polyfills).
- Singleton sessions with configurable timeout (default 60s, max 5min).
- Localhost-only WebSocket connections.
- SIGTERM → SIGKILL escalation for process cleanup.

## Output Compression

Tool output is compressed before it reaches the model context. The compressor detects the
command type by regex (<1 ms), applies type-specific filtering (strip noise, group errors,
deduplicate, show failures only), and falls back to standard truncation for unrecognized
commands. Full output is preserved on error so debugging context is never lost.

| Command | Before | After | Savings |
|---------|--------|-------|---------|
| `git status` | ~2,000 tokens | ~400 tokens | -80% |
| `git push/commit` | ~1,600 tokens | ~120 tokens | -92% |
| `npm test` (all pass) | ~25,000 tokens | ~2,500 tokens | -90% |
| `tsc --noEmit` | ~8,000 tokens | ~1,600 tokens | -80% |
| `npm install` | ~3,000 tokens | ~450 tokens | -85% |

## Structured Logging

Every pipeline run and interactive session produces JSONL logs — one JSON object per line,
parseable, grep-friendly, timestamped.

```
.skillfoundry/logs/
├── session.log                   # Rolling log for interactive mode (last 1000 lines)
├── forge-20260305-abc123.log     # Per-pipeline-run log
└── ...                           # Auto-cleanup keeps the last 20
```

```jsonl
{"ts":"2026-03-05T12:07:14.123Z","level":"INFO","category":"pipeline","event":"phase_start","data":{"phase":"FORGE"}}
{"ts":"2026-03-05T12:07:15.456Z","level":"ERROR","category":"provider","event":"connection_error","data":{"provider":"openai","error":"ECONNREFUSED"}}
{"ts":"2026-03-05T12:07:16.789Z","level":"WARN","category":"provider","event":"retry_attempt","data":{"attempt":2,"delayMs":1000}}
```

Log level is set in `.skillfoundry/config.toml`:

```toml
log_level = "info"   # debug | info | warn | error
```

`debug` adds per-turn token counts and tool-call tracing. The default `info` captures phase
transitions, gate results, and errors.

## Memory Bank

```
memory_bank/
├── knowledge/
│   ├── bootstrap.jsonl          Pre-seeded framework knowledge
│   ├── facts.jsonl              Verified technical facts
│   ├── decisions.jsonl          Design decisions with rationale
│   ├── errors.jsonl             Error patterns and their solutions
│   └── preferences.jsonl        User preferences and conventions
├── relationships/
│   ├── knowledge-graph.json     Node/edge relationship graph
│   └── lineage.json             Correction chains and lineage
└── retrieval/
    ├── query-cache.json         Recent query cache
    └── weights.json             Weight adjustment history
```

Storage is append-only JSONL with weighted relevance ranking. Entries start at weight 0.5.
Validated-by-test entries gain +0.2; retrieved-and-used entries gain +0.1. A corrected entry
drops to 0.3 while its correction starts at 0.7. Higher weight means higher retrieval
priority.

Every `/forge` run harvests automatically — run summaries, failed-story errors, micro-gate
findings, and gate verdicts are written without manual invocation.

Cross-project sync pushes lessons to a central Git repository and pulls global lessons back.
`scripts/harvest.sh` extracts decisions, errors, and patterns from one or all registered
projects; entries repeating 3+ times across projects are promoted to global lessons.

## Code Map (Pre-Flight)

| What it maps | Why it matters |
|--------------|----------------|
| API contract surface (`endpoints[]`) | Agents call real endpoints with real shapes — no invented routes |
| Import + call graph | Unresolved imports caught before build; impact analysis on changes |
| DB models + layer tags | Knows what is database / backend / frontend / shared |

Backed by tree-sitter (TS/JS + Python, pure WASM). Cached at `.skillfoundry/code-map.json`
and refreshed incrementally. Runs automatically in `/forge` and `/go`, feeding
`sf_contract_check` and `sf_import_validator`. Advisory — it never blocks a run.
