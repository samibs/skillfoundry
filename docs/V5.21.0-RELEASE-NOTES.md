# SkillFoundry v5.21.0 — Codebase Agent Wiki

**Released:** 2026-07-05

---

## What's in This Release

v5.21.0 extends the `/docs` skill (the Documentation Codifier) with a repo-wide, **agent-facing wiki generator**, inspired by [langchain-ai/openwiki](https://github.com/langchain-ai/openwiki).

Until now, `/docs` treated documentation as two things:

- a **storefront** — `README.md`, written for users, and
- a **workshop log** — `CHANGELOG.md`, written for maintainers.

Phases 1–6 of the skill enforce that split, plus version consistency, cross-document integrity, and health scans. They document features **on demand**: you hand `/docs` a finished feature and it codifies it.

OpenWiki names a third kind of documentation that SkillFoundry had no equivalent for: **a map of the codebase built for the next coding agent.** v5.21.0 adds it as **Phase 7** of the skill.

---

## The Problem

An agent (or a new engineer) dropped into an unfamiliar repository burns most of its budget on *orientation* — reading files to reconstruct what the project is, how it is organized, where a given behavior lives, and what breaks if you change it. The two documents we already maintain don't help much here:

- The README is deliberately shallow (it's for users).
- The CHANGELOG is a time-ordered log, not a spatial map.

And AI-generated "architecture docs" have a notorious failure mode: they confidently describe modules, APIs, and behavior that **do not exist**. A plausible-sounding lie is worse than no doc at all.

---

## The Solution: `/docs wiki`

A new capability with three modes:

| Command | Mode | Behavior |
|---------|------|----------|
| `/docs wiki` or `/docs wiki init` | **Init** | Build the agent wiki from scratch under `docs/wiki/`. |
| `/docs wiki update` | **Update** | Surgical, change-aware refresh. May be a genuine no-op. |
| `/docs wiki audit` | **Audit** | Report wiki freshness vs. current git HEAD, without editing. |

Output lives in `docs/wiki/` — separate from hand-authored `docs/` and the user-facing `README.md`. The entrypoint is always `docs/wiki/quickstart.md`: a high-level overview, a "Start here" list linking every section, a "Key source files" list, and a "Notes for future agents" section.

### Grounding discipline (anti-hallucination)

The core rule that separates this from generic AI doc generation:

- Ground **every** important claim in a source file, existing doc, or git evidence actually inspected.
- Do **not** invent files, modules, APIs, routes, business rules, or config keys.
- Prefer "unknown / needs verification" over a plausible guess.
- Include inline source references so any reader can verify or continue exploring.

### Git-as-discovery

The wiki explains **why** code exists, not just what files contain. Init runs use `git log`/`blame`/`show` selectively on high-signal files. Update runs inspect commits added since the last successful run via the `gitHead` recorded in `docs/wiki/.last-update.json`.

### Surgical, change-aware updates

Update runs build a **docs-impact plan** — `source change → wiki page affected → edit needed → why` — and apply a **soft diff budget**: fewer than ~5 changed source files touches at most 1–2 wiki pages. No formatting-only edits. If nothing relevant changed and the wiki is already accurate, the run edits nothing and reports "wiki already current."

### Agent-actionable pages

Every section page carries a **"where to start / what to watch out for / relevant tests"** trio — the thing that makes the wiki drive change rather than passively inventory files. Navigability rules prevent thin pages and single-file-directory sprawl: one canonical home per concept, small repos collapse to `quickstart.md` + 1–2 pages.

### Agent instruction file integration

So future agents actually find the wiki, the run ensures the top-level `AGENTS.md`/`CLAUDE.md` carries a reference section pointing to `docs/wiki/quickstart.md`. Edits are idempotent and preserve surrounding instructions.

### Security

Never reads or documents `.env` files or secret values. All output stays under `docs/wiki/`; the only files outside it the run may touch are top-level `AGENTS.md`/`CLAUDE.md`, and only for the reference section.

## Cross-Platform

Ran `scripts/sync-platforms.sh sync documentation-codifier` so the enhanced skill regenerated across all six install platforms:

- `.claude/commands/docs.md` (Claude Code)
- `.copilot/custom-agents/docs.md` (GitHub Copilot)

---

## Upgrade Notes

- **No breaking changes.** This is a capability upgrade to an existing skill — no new commands, no new agents, no schema or config changes.
- **No version drift.** The `docs` skill's own Phase 1/6 consistency rules were followed for this release.
- Try it: from any repo, run `/docs wiki init`, review `docs/wiki/quickstart.md`, then keep it current with `/docs wiki update`.
