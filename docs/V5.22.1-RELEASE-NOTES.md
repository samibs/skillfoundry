# SkillFoundry v5.22.1 — Consistency Follow-up

**Released:** 2026-07-06

---

## What's in This Release

A small patch that closes out the [v5.22.0 Refinement Pass](V5.22.0-RELEASE-NOTES.md) with two hygiene fixes. **No runtime behavior changed** — this is documentation, comments, and a comment-only rebuild.

### Skill/agent counts reconciled to verifiable ground truth

The docs stated the skill count **six different ways** (`63 / 64 / 65 / 60 / 66`) and the agent count **four ways** (`53 / 54 / 56 / 60`) — none matching what's actually on disk. Every count is now anchored to a reproducible source:

- **107 skills** per platform — the number `install.sh` reports.
- **61 core agents** — the framework's own `AGENT_REGISTRY`, whose test asserts `toHaveLength(61)`.

Propagated to the site changelog metrics (`54/66/64/60/60/61` → `61/107×5`), homepage stats, the README (Supported Platforms table, IDE Skills header + tree), `docs/AGENTS.md`, `docs/QUICK-REFERENCE.md`, `docs/DOCUMENTATION-INDEX.md`, and `site-docs/docs/architecture.md` (`88` → `112` agent prompt files).

It also corrected a genuine **stale count inside the registry itself** — the source comment `// Registry: all 60 agents` (→ 61) and the `FULL (21 agents)` category tally (→ 23, the real count) — and in `docs/TEST-SUITE-REFERENCE.md`, which described the registry test as expecting 60 when it actually asserts 61. `INDEX-v2` now carries the honest breakdown so the three legitimately-different numbers never get conflated again: **61 registry · 56 persona files · 52 slash-command skills**.

### `sf_cli` dist rebuilt to match source

The committed `dist/` was compiled from source that predated the JSDoc doc-comments later added to `core/{agent,gates,pipeline}.ts` (and lagged the registry `61` comment). A clean `tsc` rebuild produced a diff that is **entirely comment/JSDoc additions** — verified line-by-line, no functional or behavioral code changed, and the build is idempotent. Tracked `dist` is back in sync with tracked `src`.

> Note: the per-agent tool optimization was never at risk. Each agent's tools resolve at call time via its `toolCategory` + `getAgentTools()`, not a stored `tools` field.
