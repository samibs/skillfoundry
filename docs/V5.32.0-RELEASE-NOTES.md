# SkillFoundry v5.32.0 — AI Delivery Efficiency

**Released:** 2026-09-04

---

## What's in This Release

One change: effort now scales with risk.

AI agents are rarely wrong. They are usually **expensive** — re-reading the same repository,
re-running the same suite, re-reviewing the same unchanged diff, and continuing long after
the change was already proven correct. Run a wave of them in parallel and most of the compute
goes into rediscovery.

> **Do not perform more engineering activity than is necessary to prove the requested change
> correct.**

A shorter execution is not automatically better. A longer execution is not automatically
safer. The correct execution is the **minimum defensible** one that produces sufficient
evidence of correctness.

```
Agent effectiveness = accepted useful change / (elapsed time × compute cost × human attention)
```

Additive and on by default. One setting restores the previous always-validate-everything
behavior.

## Delivery budgets

Every task is classified before implementation — **deterministically**, from path patterns
and keyword sets, with no model call. The same task always lands in the same budget, with an
auditable reason and the matched signals recorded.

| Budget | Work | Validation |
|---|---|---|
| **LOW** | CSS, text, small config, isolated rename, docs | inspect → implement → type-check → smoke → diff → stop |
| **MEDIUM** | Normal feature, focused endpoint, business rule, DB query | scoped analysis → implement → targeted tests → affected build → acceptance → stop |
| **HIGH** | Auth, security, crypto, migration, infrastructure, concurrency, transactions, deployment, secrets, public API, financial/compliance | plan → dependency analysis → implement → targeted + integration → **security checks** → broad build → acceptance → regression → review |

A LOW task cannot trigger the repository-wide suite. A MEDIUM task cannot trigger all-project
validation without evidence the change reaches that far.

## Already proven + unchanged = do not prove again

A validation is recorded with the **content hash of every file it depended on**, alongside
base commit, tree hash, command, scope, result, duration and producer.

| Answer | Meaning |
|---|---|
| `REUSE` | Already proven against this exact state. Skip it. |
| `FIX_FIRST` | Already **failed** against this state. Re-running unchanged proves nothing. |
| `WAIT` | Another worker is running it. Consume its evidence. |
| `RUN` | Genuinely needed, and the claim is yours. |

Scoped evidence survives an unrelated edit and dies precisely when one of its own files
changes. Repository-wide evidence is bound to the whole tree hash — deliberately
conservative, because when dependency impact is unclear the safe answer is to re-run.

## Three workers, one suite

```
Worker A → targeted validation ┐
Worker B → targeted validation ├→ integration gate → repository-wide validation ONCE
Worker C → targeted validation ┘
```

The first worker to claim a validation runs it; the others are told who holds it and consume
the result. The claim is an atomic `mkdir` — a directory rather than an exclusive file create,
because `mkdir` is atomic on NFS as well as local POSIX and Windows filesystems, where
`O_CREAT | O_EXCL` on a regular file is not. A claim past its TTL is reclaimed, so a crashed
worker cannot deadlock the wave.

The gate verifies handoffs, aggregates the blast radius, invalidates **only what integration
itself disturbed**, reuses what survives, and runs only what is genuinely missing.

## Test scopes, and honest escalation

`smoke` · `targeted` · `affected` · `integration` · `full`

Derived from the budget, the changed files, the acceptance criteria, an explicit override,
and **measured** dependency impact. `full` is never reachable from the budget alone.

```
targeted tests fail → diagnose → fix → targeted tests pass → STOP
```

A successful fix is **not** grounds for a full-suite run. Scope escalates only when a failure
names files outside the change, or dependency analysis reveals wider impact. Budget escalation
without concrete evidence is refused — arbitrary escalation is the same waste the budget
exists to prevent.

## Measured impact, not guesses

A reverse import graph (TypeScript/JavaScript/Python), cached against the tree hash, measures
how far a change actually reaches.

**Path aliases are resolved** — `compilerOptions.paths` and `baseUrl` from `tsconfig.json`,
`jsconfig.json` and `tsconfig.base.json`. This matters more than it looks: without it a
monorepo reports nearly every first-party import as external, measured fan-out collapses
toward zero, and the layer would quietly *narrow* test scope on exactly the codebases that
need it widened.

It is deliberately a static scan — resolving a full module graph would cost more than the
validation it avoids — and honest about its limits. A specifier matching no alias and no
relative path is counted as an **unresolved import** rather than silently dropped, so a high
count means fan-out is a lower bound and callers should widen rather than narrow.

## Stop when it is proven

```
$ /delivery complete --budget MEDIUM --implemented --diff-inspected --evidence-recorded \
    --ac-proven 3 --ac-total 3 --passed-at targeted --required-scope targeted

  ✓ implementation-complete    ✓ acceptance-proven    ✓ validation-passed
  ✓ no-blockers                ✓ diff-inspected       ✓ evidence-recorded

  ✓ DELIVERY COMPLETE
    · The change is proven. Do not re-read the same unchanged diff.
    · Do not broaden test scope without evidence of wider impact.
    · Do not perform opportunistic refactoring or cleanup that was not requested.
    · Do not re-run a validation that already passed against this repository state.
```

Security checks are a mandatory, non-skippable criterion at HIGH.

---

## Safety — never optimised away

Authentication, authorization, secrets, cryptography, destructive database changes, schema
migrations, production deployment, financial integrity and compliance controls classify
**HIGH on path *or* keyword** — a change described as "a tiny tweak" that touches `src/auth/`
is still HIGH.

- A downgrade override is **refused** and logged. The deliberate escape hatch records that
  required checks are no longer guaranteed.
- Security checks cannot be skipped at HIGH.
- A test-scope override that would under-test a HIGH change is refused.
- A budget is never lowered mid-task.
- Evidence is reused only when valid for the exact relevant repository state.

## Measurement

```bash
/cost --efficiency          # or /delivery efficiency
```

Validation commands, **repeated commands**, evidence reused vs regenerated, reuse rate,
validation seconds spent and saved, and repository-wide runs avoided.

Token usage and cost come from the **real** usage ledger, attributed to each task's execution
window. That attribution is by time and says so — overlapping workers share a window rather
than being resolved exactly. A window covering no recorded provider call reports `unknown`,
never zero. **Nothing is estimated**: a fabricated token count poisons every ratio computed
from it.

```bash
/delivery plan STORY-042 --text "add a paginated orders endpoint"
/delivery impact --files src/api/orders.ts

/delivery complete --budget MEDIUM --implemented --diff-inspected …

```

`/delivery help` lists all 13 subcommands. `$forge --dry-run` and `/gate all` both consult
evidence before running the tier suite; `/gate all --force` bypasses it.

## Configuration

```toml
[delivery_efficiency]
enabled = true                      # master switch
default_budget = "MEDIUM"
evidence_reuse = true
validation_deduplication = true
test_scope_policy = "risk-based"    # or "always-full"
stop_when_proven = true
```

With `enabled = false`, every task is HIGH, every scope is `full`, nothing is reused, and
completion is reported but never enforced — the behavior SkillFoundry had before this release.
The two sub-switches are independent: reuse can be off while deduplication stays on.

## Compatibility

- **Fully backward-compatible and additive.** No existing command, gate or pipeline changes
  behavior. A config written before this release keeps working; unknown values are ignored
  rather than adopted.
- **No schema migration.** The evidence store, shared context and import graph are
  regenerable caches under `.skillfoundry/` — deleting them costs time, never correctness.
- Evidence payloads are size-bounded; an oversized in-process result is **dropped rather than
  truncated**, because half a gate summary would be worse than none.

## Also fixed

A latent defect in the v5.31.0 mission code: `git()` trimmed stdout, and `git status
--porcelain` encodes state in columns 1-2. Trimming strips the leading space of an unstaged
entry (` M src/x.ts` → `M src/x.ts`), so a fixed-column parse ate the first character of every
first path — `rc/x.ts`. It could misclassify a governance path as product. Fixed with
`preserveOutput`, plus parsed `paths` exposed so callers stop re-parsing display strings, and
`untrackedFiles: 'all'` so a brand-new module is visible as files rather than a collapsed
`src/`.

## Tests

**264 new tests across 4 files, all passing** — 619 including the mission, config, command,
forge, gates and budget suites this touches. A full repository run is green apart from five
failures proven pre-existing by running the same suite at the base commit.

Defects found by these tests and fixed before release:

1. `allowUnsafeOverride` was dead code — `maxBudget` raised the level straight back to HIGH.
2. With evidence reuse disabled, deduplication silently stopped working, because the reuse
   short-circuit returned before a claim was taken.
3. The first `$forge` wiring re-ran the gate suite "to render the detail" on a reuse — which
   would have made the reuse a relabelled re-run saving nothing. Fixed by inlining the
   compact result into the evidence entry, with a test asserting the work runs exactly once.
