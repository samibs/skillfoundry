# SkillFoundry v5.26.0 — Domain Expert Synthesis

**Released:** 2026-07-11

---

## What's in This Release

When you build software for a specialized **non-IT domain** — law, accounting, real estate,
medical, insurance, tax — the generic model produces output that is *technically correct but
professionally wrong*: grammatically valid French that no jurist would sign, an accounting
entry that balances but uses the wrong term for the local chart of accounts, a contract clause
in the wrong legal register. The output *looks* fine, so the gap ships silently.

v5.26.0 adds **Domain Expert Synthesis**: SkillFoundry detects when a project needs a
specialized non-IT reviewer and synthesizes a **project-scoped, review-only domain reviewer**
for it — grounded in a citable knowledge pack, promoted to the framework when it recurs. All
three phases (detection → synthesis → cross-project promotion) ship together.

The headline rule: **these reviewers review, they never advise.** A reviewer checks
vocabulary, terminology, register, and way-of-working and returns findings; it never gives
advice or makes a legal/financial/medical determination. That is what makes the feature useful
instead of a liability.

---

## The core idea: correct ≠ professionally right

A domain reviewer is to prose what `/review` is to code — a **review pass** over content the
framework already produced. It checks four things against how a qualified practitioner in the
field actually works:

- **Terminology** — the correct term of art; flags generic or wrong-field vocabulary
- **Register** — the professional tone/formality expected in the jurisdiction and language
- **Standard phrasings** — mandatory or conventional clause/statement forms
- **Way-of-working** — the structure, order, and conventions practitioners expect

Its output is a findings list — `{span, issue, suggested_rewrite, citation}` — never a
determination. Asked *"is this contract valid?"*, it declines the judgement and reviews the
wording instead, deferring the substantive call to a qualified human.

## Three ways a gap is detected

1. **Self-flag (Phase 1).** An agent producing specialized non-IT output raises a
   `domain-expertise-gap` — the shared module `agents/_domain-gap-protocol.md` governs it.
   This catches the case with zero history: the first time it happens.
2. **Behavioral (Phase 2).** The same domain corrected 3+ times is surfaced.
   `scripts/domain-gap-scan.sh record` logs each correction; `scan` reports domains at the
   threshold.
3. **Declared (Phase 2).** A PRD can declare `domains: [legal-fr, accounting-lu]` in its front
   matter; `/onboard` asks about specialized domains up front.
   `scripts/domain-gap-scan.sh from-prd` surfaces them.

In all three, the guard runs first: **IT domains are never synthesized** (denylist + skill
registry), so the framework's existing IT skills are reused, not duplicated.

## Synthesis, grounding, and safety

- **Synthesis** — `scripts/synth-expert.sh synthesize` writes a project-local reviewer to
  `.claude/commands/<slug>-expert.md` (mirrored to every installed platform) plus an
  auto-scaffolded knowledge pack `packs/<slug>/` (`pack.json`, `rules.jsonl`, `SOURCES.md`).
- **Grounding** — every finding cites a pack entry or is marked `⚠ unverified` (cite-or-flag).
  Packs ship **empty**: real, cited terminology is authored and human-reviewed, so the reviewer
  can't present invented rules as authoritative.
- **Safety** — review-only mandate, mandatory "not legal/tax/financial/medical advice"
  disclaimer, human-in-the-loop. Synthesis **never runs unattended**: a non-interactive run
  without explicit confirmation logs the gap and exits without writing.

---

## Cross-project promotion (Phase 3)

A reviewer earned on one project stays project-local. When the **same domain is synthesized in
3+ distinct projects**, it graduates to the shared framework and every future project inherits
it. This runs inside `/evolve` (Step 3.5):

```
bash scripts/promote-experts.sh scan                    # domains in ≥3 projects, not yet shared
bash scripts/promote-experts.sh promote --domain <slug> # → agents/<slug>-expert.md (framework)
```

Provenance is aggregated from each registered project's `memory_bank/knowledge/experts.jsonl`.

| Command | Purpose |
|---------|---------|
| `/domain expert <description>` | Synthesize a review-only reviewer (+ knowledge pack) for a non-IT domain |
| `/domain experts` | List synthesized reviewers in this project |

New scripts: `scripts/synth-expert.sh`, `scripts/domain-gap-scan.sh`,
`scripts/promote-experts.sh`. New shared module: `agents/_domain-gap-protocol.md`.
`/onboard` gains a specialized-domain question; `/evolve` gains a promotion step.

## Also in this release

- **Bootstrap seed fix.** `install.sh` no longer aborts when the `bootstrap.jsonl` seed is
  absent, and the seed is refreshed to 32 curated, privacy-clean entries (correct platform
  count, current versioning, and universal security/quality rules).
- **Harvest privacy fix.** `harvest.sh` no longer auto-appends raw promoted entries (with
  `source_project`, `signature`) into the shipped `bootstrap.jsonl` — that path was re-leaking
  private cross-project names/paths into the public seed on every harvest sweep.
- **Test suite green.** The seven long-standing `tests/run-tests.sh` failures were fixed
  (a2a-server.sh `set -e` abort on command-less agents, stale agent-count cap, dual-nature
  agent handling, CLAUDE.md size). Suite: **198 passing, 0 failing.**
- **Release pipeline fix.** The npm publish job now targets `sf_cli/` (publishing
  `@skillfoundry/cli`, not the root package) and no longer trips over a committed `.npmrc`.
